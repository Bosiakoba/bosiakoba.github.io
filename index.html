🤔 What Makes straw Special?

straw solves a critical challenge faced by modern AI applications: how to efficiently share and store vast amounts of data across multiple machines without the complexity of traditional databases or object storage systems.

🔄 Smart Data Flow

Workers on multiple machines can read and write data through a shared mounted filesystem. Instead of moving huge files around, they exchange small references that point to the actual data. This saves enormous amounts of network bandwidth and time.

🚄 Built for Performance

The core storage and queue protocols run in Rust - one of the fastest programming languages available. Python APIs work seamlessly with common AI data formats including bytes, NumPy arrays, and PyTorch tensors.

🔌 Works Everywhere

Currently optimized for JuiceFS shared mounts with Linux/POSIX filesystem operations. Local filesystems work great for development and testing. Support for NFS and other network filesystems is on the way.

⚡ Production Ready

straw already powers real-world AI systems in the slime project, handling rollout-to-rollout and rollout-to-training queues with shared tensor storage.

🏗️ How Does It Work?

Let's break down what makes straw so powerful - without getting too technical!

  1. Shared Filesystem Foundation: Instead of a central server, straw relies on a shared filesystem that everyone can access.
  2. Smart References: When data needs to be shared, only small reference files are moved around. The actual heavy data stays put in the shared storage.
  3. Durable Queues: Rollout-to-training pipelines use filesystem-based queues that survive crashes and restarts without losing data.
  4. Efficient Packing: Data is packed efficiently before being written to storage, minimizing space and maximizing speed.

👩‍💻 Simple Python Interface

One of straw's best features is how easy it is to use. The Python API accepts common data types directly:

# Example usage pattern (illustrative):

from straw import Queue

import numpy as np

import torch


queue = Queue("my-pipeline")

arr = np.array([1, 2, 3])

queue.put(arr)

tensor = torch.tensor([4, 5, 6])

queue.put(tensor)


# Retrieve on another machine:

from straw import Queue

queue = Queue("my-pipeline")

data = queue.get()
